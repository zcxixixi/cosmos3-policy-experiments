# 语言到底怎么进入动作计算？

我们固定相机输入和初始噪声，比较“拿牛奶 / 拿黄油”。测试原始布局和牛奶移动15厘米的布局，各用三个种子，共12组完整动作预测，保存每次去噪的真实动作头输入。

| 对照 | 首次去噪数组变化 | 末次去噪数组变化 | 最终归一化XYZ差异 |
|---|---:|---:|---:|
| 原位置，换目标名称 | 2.04% | 8.65% | 0.006920 |
| 移动15cm后，换目标名称 | 2.30% | 8.61% | 0.012168 |
| 保持拿牛奶，移动15cm | 12.66% | 37.75% | 0.303437 |

表中是三个种子的平均值，差异单位不是厘米。语言相关差异持续到末次去噪，不支持“语言在中间完全消失”。

接着做80组路径替换：固定接收者的GEN视觉和动作输入，只替换生成分支读取的文本K/V，原文本分支的残差输出保留。干预作用于所有GEN token，包括视频和动作，并非只改动作queries。

我们分别换目标词、词前的文本、词后的文本，以及完整文本读取路径；测第一次、第11、第21和第30次去噪，并扫描6层窗口。

在最后一次去噪中，原始场景只换目标词，沿完整换指令差异方向恢复约15%；换词后的文本状态约89%。移动15厘米的场景对应约5%和95%。这些数字描述一个很小的语言造成的Flow输出差异，不能解释为抓取成功率，也不能把各组比例相加。

两个关键检查：词前的替换精确不改变输出；全部文本K/V替换精确复现固定GEN输入下另一条指令的输出。证明这些路径确实在计算中起作用。

模型内部的语言数据被使用了，但这还没证明它理解了目标身份。当前证据不足以定位“坏了的那一层”。

[result.json](result.json)包含全部80组干预、逐层数值、真实输出头行空间分析和检查结果。后者只是几何投影，不能用它直接诊断输出头损坏。已知此前读取输出头属性的分析脚本错误已修正；最终记录完成，且两个实际执行使用过的原生动作块精确复现。
