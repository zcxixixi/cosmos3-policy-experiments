# 09：关掉多出来的系统提示，还会抓错吗？

关掉这段提示后，抓错对象的问题仍然存在。原布局下，说“拿黄油”还是抓牛奶；把牛奶移远15厘米后，说“拿牛奶”还是抓奶酪盒。因此，不能把此前的抓错全部归因于这段额外提示。

我们怀疑的是调用方式：当前输入前面自动加了“根据提示生成视频”的系统消息，比公开 LIBERO 配置多出19个文字编码。它可能影响动作，所以这次明确打开或关闭这个开关，核对模型实际收到的完整文字，而不是只改显示在界面上的指令。

怎么改：保留同一模型、图片、动作转换和采样设置，只切换 `use_system_prompt=True/False`。先做36组离线动作预测；随后新增5条实际执行、每条128步，并复用3条已有的“开启”执行作对照。离线预测没有让机械臂执行，不能和实际执行次数相加。

删除这段提示也会把后面内容的位置编号往前挪。为避免把编号变化全部当作文字内容的作用，离线预测还加入了保留或交换这些编号的对照；这些额外对照没有做实际执行。

实际抓了谁：下表中的物体均出现模拟器抓取接触，并随后明显抬起；“抓起”不等于已经放进篮子。

| 布局 | 指令 | 开启系统提示 | 关闭系统提示 |
|---|---|---|---|
| 牛奶原位置 | 拿牛奶 | 牛奶，[已有视频](../02-object-position/center-milk/actual.mp4) | 牛奶，[新视频](closed-loop/center_milk_off/actual.mp4) |
| 牛奶原位置 | 拿黄油 | 牛奶，[已有视频](../02-object-position/center-butter/actual.mp4) | 牛奶，[新视频](closed-loop/center_butter_off/actual.mp4) |
| 牛奶移远15厘米 | 拿牛奶 | 奶酪盒，[已有视频](../06-milk-moved-15cm/native/actual.mp4) | 奶酪盒，[新视频](closed-loop/far_milk_off/actual.mp4) |
| 牛奶移远15厘米 | 拿黄油 | 奶酪盒，[新视频](closed-loop/far_butter_on/actual.mp4) | 奶酪盒，[新视频](closed-loop/far_butter_off/actual.mp4) |

这说明额外提示确实会改变部分动作数值，但关闭它没有让这些场景按目标名称选对物体。换“牛奶／黄油”也确实产生了不同的动作数组，不能说语言完全没有进入计算；数组不同仍不足以证明正确理解或选择了目标。

尚不能断言：这不是官方完整运行方式的等价验证，也不知道社区作者训练这份权重时是否改过系统提示。图像缩放、采样时间表等其他调用差异仍需分别核对。这里只有两个固定布局，实际执行使用同一组噪声种子；位置编号对照也仍会改变系统文字是否存在，不能单独测出一句话的纯语义作用。

[语言改动的动作数值图](language_effect.png)和[模型内部数组对照图](readout_heatmap.png)用于查看差异，不代表“理解程度”或抓取成功率。完整资料见[36组离线结果](result.json)、[原始动作数组](arrays.npz)、[5条新增执行结果](closed-loop/result.json)和[离线完成记录](probe_complete.json)。

**数值与复核细节**

36组离线预测由24组普通开关对照和12组位置编号对照组成：两个布局、两条目标指令、噪声种子195／196／198；三个额外编号设置只在198上运行。开启时文字长度140，关闭时121；关闭后的121项编码与开启输入去掉前19项后的数组逐项相等。

所有12组开启预测都精确复现已有开启动作数组。配对预测保留相同的 FP32 初始图像／动作状态和采样时间表；种子198的20份完整保存状态也重新以 CPU 读取，核对了初始数组、文字和位置编号。[完整状态文件清单与校验值](internal_state_files.json)记录远端保存位置，本仓库提供[部分内部数值](numerical_examples.json)和[完整4096维示例向量](readout_vectors.npz)。
