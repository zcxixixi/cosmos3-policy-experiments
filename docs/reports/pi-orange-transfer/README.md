# π 橙汁修正跨布局验证

完全复用上一轮 adapter.npz，SHA-256 一致。仍为橙汁指令下动作专家 L16 每次去噪减去固定向量，10 次去噪、224×224 模型输入，未重训、未改强度、未根据本轮结果挑层。

## 场景

xm、yp 是已保存的牛奶物体位移布局，没有用于橙汁成功/失败均值方向提取；但旧拟合的种子偏移估计使用了这些布局的健康奶酪控制，因此不是完全未接触输入。canonical0/1 是官方 LIBERO-object 橙汁任务的两个初始状态，与原先牛奶任务中只换橙汁指令的场景不同；这两个条件均未用于本修正拟合。测试只传画面、状态和指令，不传物体坐标。

每种布局使用新种子 12000/12100，各跑原模型和修正，共 16 次闭环，每次最多 200 步。统计首次稳定抓起正确物体（双指接触、抬高 2cm、持续 5 帧），不等于完成入篮。

| 布局 | 原模型抓对橙汁 | 同一修正后 |
|---|---|---|
| 旧布局 xm | 0/2 | 2/2 |
| 旧布局 yp | 0/2 | 2/2 |
| 官方橙汁场景：初始状态 0 | 2/2 | 0/2 |
| 官方橙汁场景：初始状态 1 | 2/2 | 0/2 |

逐对首帧相机图片、机器人模型输入逐元素一致；初始 qpos 按绝对误差 1e-12 核验，官方任务经过热身后存在约 1e-16 的浮点舍入差异。物体位置没有人为改动。同一 seed+query 生成同形状初始动作噪声；后续观测随各自动作分叉。

没有把不同位置当成不同新任务夸大：xm/yp 是同桌面干扰物布局变化，canonical0/1 是同一个官方橙汁任务的两个初始化。两个种子只提供小样本迹象，不能证明一般场景泛化。

## 结论

旧桌面的两个干扰物布局合计由 0/4 改善到 4/4；官方橙汁任务的两个初始化由 4/4 退化到 0/4（全部未稳定抓起）。所有 8 对总体正确数为 4/8 → 4/8，净收益为零，但修复了四个错误、同时破坏了四个正确行为，不能称为通用提升。

固定向量对一类场景有局部价值，但仅按“orange juice”指令启用不够。下一步需要根据画面或隐状态判断是否需要修正，并用原本正确的场景作保护训练/验证；这项条件判断尚未实现或验证。不应全局部署本修正。临时服务已关闭。
