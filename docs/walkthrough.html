把一次真实的计算摊开看

场景：牛奶移远 15 cm，指令“pick up the milk box and place it in the basket”。下面每个数字都来自 A6000 上实际保存的一次计算：第一次去噪、第 36 层。

① 输入

模型实际收到的文字，不是“抓牛奶”四个字

它收到一段 JSON 文本，被切成 122 个 token（小碎片）。你的那句话只占其中很小一段，其余是固定的格式。红色是目标名字，也就是我们换来换去的那两个词。

0<|im_start|>1user2\n3{"4cin5emat… 到第 43 个 …一堆固定格式 44"45pick46up47the 48milk49box 50and51place52it53in54the55basket… 到第 114 个 …idle_frame 等 115<|im_end|>117<|im_start|>118assistant121<|vision_start|>

画面也被切成 token：

· 当前画面 50 个
· 模型自己预测的未来画面 200 个（4 帧 × 50）
· 动作 16 个（16 步）

文字 + 画面 + 动作，合起来一共 388 个 token，就是网络每次计算要处理的全部。

② 地址表

388 个 token 各自住在哪

文字 · 0–121 · 122 个
当前画面 · 122–171
未来画面 · 172–371 · 200 个
动作

动作 token 的地址是 372–387。第 36 层里，这 16 个动作 token 各自要决定“去看这 388 个里的谁”。

③ 测量：动作在看谁

第 36 层，动作 token 把注意力给了谁？

下面是真实算出来的注意力分配：16 个动作 token，32 个注意力头取平均，加起来是 100%。左边是“牛奶盒”指令，右边是“奶酪”指令，两次的画面、噪声完全一样。

指令：…milk box…
文字（122 个）0.77%
当前画面（50 个）14.8%
未来画面（200 个）49.1%
动作自己（16 个）35.3%
指令：…cream cheese…
文字（122 个）0.77%
当前画面（50 个）14.6%
未来画面（200 个）49.0%
动作自己（16 个）35.6%

文字占 122 个 token，如果平均看，应该拿到约 31%。实际只有 0.77%。而且这 0.77% 里，约 91%（0.70%）给了第 0 个 token <|im_start|>，一个固定的开头符号，和你说了什么无关。

④ 放大到目标名字

“milk box”这两个词，拿到了多少注意力？

平均看的话实际差多少
token 48、49（milk box）0.52%0.00074%少约 700 倍
token 48、49（cream cheese）0.52%0.00098%少约 500 倍

换句话说：在最后一层、第一次去噪时，动作 token 几乎不看目标名字。32 个头里，最“爱看文字”的那个头，也只把 4% 的注意力给了整个文字段。

⑤ 这说明什么，不说明什么

读这些数字要小心

说明的：在这次计算的第 36 层，语言进入动作的“口子”几乎是关着的。这与实验 18 一致，也是它的一个可能解释：我们在第 36 层把文字换成另一个目标，目标没变，可能是因为这一层本来就没怎么读它。这个解释还没有被直接检验。

不说明的：

· 只看了一层、一个时刻、一个场景。第 1–35 层、其余 29 次去噪，这次没有存全部数据，还不知道。语言完全可能是在更早的层被读进去的，到第 36 层只是已经用完了。
· 注意力大小不等于影响力。一个 token 即使只被看一点，它的内容向量如果很大，仍然可能有影响。所以“几乎不看”只是强线索，不是定论。
· 只有一次运行。种子 198、牛奶移远 15 cm、两个指令。

我怎么确认算对了：用保存下来的 Q、K、V 重新算一遍注意力，得到的输出和模型当时的真实输出相差 0.17%（相对 L2），在 BF16 精度范围内。
